Big-O Complexity

The language of efficiency

Big-O describes how an algorithm's time or space grows as the input size n grows — focusing on the dominant term and ignoring constants. It's the first thing an interviewer asks after you code: "what's the time and space complexity?"

Big-ONameExample
O(1)ConstantHash lookup, array index
O(log n)LogarithmicBinary search
O(n)LinearSingle loop over input
O(n log n)LinearithmicEfficient sorting
O(n²)QuadraticNested loops over input
O(2ⁿ)ExponentialNaive recursion (e.g. plain Fibonacci)
💡 Always state both
Quote time and space. A hashmap often turns an O(n²) brute force into O(n) time at the cost of O(n) space — naming that trade-off out loud is exactly what interviewers reward.

03

Pattern Playbook I

Hashing · Two Pointers · Sliding Window · Binary Search
Hashing / frequency map
Signal: "have we seen…", counting, dedupe, "two things that sum to X."
Trade space for speed — O(n) with a Dictionary/HashSet. (Two Sum is the canonical example.)
Two Pointers
Signal: a sorted array, pair/triplet sums, palindrome check, removing duplicates in place.
Two indices moving toward/with each other → O(n) instead of O(n²).
Sliding Window
Signal: "longest/shortest subarray or substring meeting a condition."
Expand/shrink a window over the array → O(n) instead of recomputing each range.
Binary Search
Signal: sorted input, or "find the minimum value that satisfies…"
Halve the search space each step → O(log n). Watch the boundary conditions.
C#Two Sum — hashing in O(n)
int[] TwoSum(int[] nums, int target) {
    var seen = new Dictionary<int,int>();
    for (int i = 0; i < nums.Length; i++) {
        int need = target - nums[i];
        if (seen.ContainsKey(need)) return new[]{ seen[need], i };
        seen[nums[i]] = i;
    }
    return Array.Empty<int>();
}
04

Pattern Playbook II

Recursion/Backtracking · Trees (BFS/DFS) · Stack
Recursion & Backtracking
Signal: "generate all combinations/permutations/subsets," puzzles, exploring choices.
Make a choice, recurse, then undo it ("backtrack"). Always define the base case first.
Tree DFS / BFS
DFS (stack/recursion): depth, paths, "does a path exist." BFS (queue): shortest path / level-order. Most tree & graph questions are one of these two.
Stack
Signal: matching/nesting (valid parentheses), "next greater element," evaluating expressions, undo. LIFO is the clue.
Queue / BFS
Signal: shortest path in an unweighted graph/grid, level-by-level processing. FIFO is the clue.
C#BFS skeleton (level-order)
var q = new Queue<Node>(); q.Enqueue(root);
while (q.Count > 0) {
    var node = q.Dequeue();
    // process node
    foreach (var child in node.Children) q.Enqueue(child);
}
05

Pattern Playbook III & Dynamic Programming

Linked List · Heap · DP
Linked List
Signal: reverse a list, detect a cycle, find the middle. Tools: dummy head node, and fast/slow pointers (Floyd's) for cycle/middle.
Heap / Top-K
Signal: "K largest/smallest," "K most frequent," merge K lists, running median. A heap keeps the best-K in O(n log k).
Dynamic Programming — the one to demystify

DP solves problems by breaking them into overlapping subproblems and storing each subproblem's answer so it's computed once. Two forms: memoization (top-down recursion + a cache) and tabulation (bottom-up filling a table).

📖 When it's DP
Two signals together: optimal substructure (the answer is built from answers to smaller subproblems) and overlapping subproblems (the same subproblem recurs). Classic starters: Fibonacci, climbing stairs, coin change, longest common subsequence, 0/1 knapsack. Plain recursive Fibonacci is O(2ⁿ); adding a cache makes it O(n) — that contrast is the DP lesson.
💡 At 4 YOE
You're rarely expected to solve hard DP under pressure, but you must recognise a DP problem, explain memoization vs tabulation, and code an easy/medium one (climbing stairs, coin change). Don't over-invest in advanced DP at the expense of the high-frequency patterns above.

Solving Approach & Interview Prep

A repeatable method + practice questions
1
Clarify — inputs, outputs, constraints, edge cases. Ask before coding.
↓
2
Brute force first — state a working approach + its complexity out loud.
↓
3
Optimise — which pattern fits? Often hashing/two-pointers/window removes a loop.
↓
4
Code, then test — walk an example, check edge cases (empty, one element, duplicates).
⚠️ Communicate, don't go silent
Interviewers grade your thinking, not just the final code. Narrate your reasoning, state complexity, and admit trade-offs. A clear thought process with a brute-force solution often beats silent struggle toward the optimal.
Q1What's the time complexity and how would you improve a nested-loop solution?
AA nested loop over the input is O(n²). I'd look for a hashing pattern — storing what I've seen in a Dictionary or HashSet to make lookups O(1) — which often drops it to O(n) time at O(n) extra space, like turning the brute-force Two Sum into a single pass.
Q2When do you use BFS vs DFS?
ABFS, using a queue, explores level by level and is the go-to for shortest paths in unweighted graphs or grids and for level-order traversal. DFS, using recursion or a stack, explores as deep as possible first and suits path existence, exploring all paths, and problems naturally defined recursively.
Q3How do you detect a cycle in a linked list?
AFloyd's fast/slow pointers: advance one pointer by one node and another by two. If they ever meet there's a cycle; if the fast pointer reaches the end there isn't. It's O(n) time and O(1) space, beating a HashSet of visited nodes on space.
Q4What makes a problem dynamic programming, and what are the two styles?
AIt's DP when there's optimal substructure — the answer is built from smaller subproblem answers — and overlapping subproblems that recur. The two styles are memoization, which is top-down recursion with a cache, and tabulation, which builds a table bottom-up. Caching turns exponential recursion like naive Fibonacci into linear time.
Q5How would you find the K most frequent elements?
ACount frequencies in a Dictionary in O(n), then use a min-heap of size K, pushing each element and popping when it exceeds K, so the heap ends holding the top K in O(n log k). That beats fully sorting all counts when K is much smaller than n.

What a 4 YOE Engineer Must Know

Master vs. skip
✅ Must Know
  • ✓Big-O and stating time + space
  • ✓Core structures & their costs (+ C# names)
  • ✓Hashing, two pointers, sliding window, binary search
  • ✓BFS/DFS, stack/queue, recursion/backtracking
  • ✓Linked-list tricks, heap/top-K, easy-medium DP
  • ✓A spoken solving framework + communication
⏭️ Can Skip for Now
  • ○Hard DP (interval, bitmask, digit DP)
  • ○Advanced graphs (Dijkstra/MST/topo) unless senior
  • ○Segment trees, tries, union-find depth
  • ○Memorising 500 problems — learn patterns

Big-O: O(1)<O(log n)<O(n)<O(n log n)<O(n²)<O(2ⁿ). Always state time AND space.
Structures: array (index O(1)), hashmap/set (O(1) lookup), stack (LIFO), queue (FIFO), heap (top-K, O(log n)), tree, graph.

BFS (queue, shortest path/levels) vs DFS (stack/recursion, paths/depth). Stack = matching/next-greater.

DP: optimal substructure + overlapping subproblems. Memoization (top-down + cache) vs tabulation (bottom-up).
